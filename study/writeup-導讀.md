## 標題為什麼不是《From SPI Flash to Root Shell》

那種標題網路上幾百篇，而且它賣的是**結果**——「我拿到 root」——
而這個專案結果那一半並不稀有：這台是 EOL 裝置、漏洞都是已公開的。

`The Build Nobody Had` 賣的是**素材**：這台跑的那個 build 不在任何下載頁上，
而它剛好卡在廠商修補的正中間。**那一段只有從矽晶片上讀得到**，
所以任何人想重做這一段，都得先去買一台一樣的路由器並且把 flash 讀下來。

副標賣第二件：五十六個自己的儀器 bug。第一件讓人點進來，第二件讓人讀完之後記得。

## 逐章

| 章 | 這一章唯一要讓讀者記住的 | 敵意的讀者會問 |
|---|---|---|
| **1 規則** | 「這個人的每一句話都會標明它是在哪個檔案上量的」 | 「規則寫得漂亮，那你哪一條自己違反過？」→ 正文第 12 章就是答案，而且是主動端出來的 |
| **2 語料** | 雜湊只證明「你我拿到同一份」，不證明「這是廠商發的」 | 「兩個鏡像你憑什麼用？」→ 只用在比較，從不單獨支撐主張，而且明講是弱證據 |
| **3 板子** | **W01 從容器格式推出 ≥4 MB，三週後硬體證實** | 「型號都只有包裝上的字一個來源吧？」→ 對，而且那一欄空了四天；flashrom 那段是我**自己推翻自己**的更正 |
| **4 主控台** | 鮑率是**量**出來的：26 µs，而 52 µs 那一發排除掉 19200 | 「沒有 shell 是你沒找到吧？」→ 這一章只主張「登入提示字元下沒有」，第 10 章從別的門進去了 |
| **5 那個 build** 🏆 | 三步跨五年，而中間那一步只有這顆晶片上有 | 「你只有一台。」→ 對，寫在第 14 章第二段，不是藏在附註 |
| **6 `boa`** | 公告寫的是症狀（`.dat` 沒被擋），成因是**所有不含那個子字串的路徑都不擋** | 「那不就能繞過？」→ 十二種形狀，全部失敗，而且原因比「沒成功」更利：豁免比對和開檔讀的是同一個正規化路徑 |
| **7 橫讀** | **哪些結論轉移了**：機制轉移，數字不轉移 | 「你自己承認前兩週白做？」→ 不是白做，是**範圍被重新標定**，而且它生出了整整一週 W04-2 |
| **8 `COMPCS`** | CVE-2019-19823 從引用變成**一個位址**，而且是廠商自己的 binary 對過的 | 「格式是從外流 SDK 抄的吧？」→ 先從資料推、再用 `libapmib.so` 自己的 `Decode` 對，而且 checksum 那一格資料本身給不出來 |
| **9 模擬** | 「Lexra 缺指令所以模擬不起來」是**錯的**——子集永遠跑得動 | 「你補了那麼多東西，還算模擬嗎？」→ 那張「補了什麼／失真了什麼」的表比「跑起來了」重要，而且第 14 章重述一次 |
| **10 攻擊鏈** 🏆 | 結尾指著 **flash 上被改掉的九個 byte**，而那條路跟 web server 不共用任何程式碼 | 「回應裡沒有 `uid=0` 你怎麼知道執行了？」→ 這一章有一整節在講**盲注要自己設計帶外通道**，而每個通道都有對照組 |
| **11 Bug hunt** | 方法是從**閘門**出發扣掉已知 CVE，不是照公告清單走 | 「那個 miniigd 不就是 CVE-2014-8361？」→ 二十二個 `A`、零個 shell 元字元，一樣殺得死。**對照組推翻了我自己的第一版** |
| **12 儀器** 🏆 | **五十六個，沒有一個是儀器自己的自我檢查抓到的** | 「你寫這章是不是在賣誠實？」→ 反過來想：這章對我沒有任何好處，除了讓讀者相信其他十三章 |
| **13 閘門** | 2020 版修好了公告點名的漏洞，**仍然過不了閘門** | 「你的閘門只跑一個 binary。」→ 章末自己講了，而且點名第 11 章最嚴重的發現在 `miniigd` 裡，不在 `boa` 裡 |
| **14 沒證明什麼** | **沒有第二支儀器讀過那顆 flash** | 這一章的存在就是為了讓這個問題**問不出來**——它已經在裡面了 |

## 三條貫穿全篇的規則，以及它們各自防的東西

| 規則 | 防的是 |
|---|---|
| 每一條主張指得回一個**可重新產生**的產物 | 「我在 Ghidra 裡看到」這種不可查證的句子 |
| 不放截圖，除非那個東西本質上是視覺的 | 截圖不能 grep、不能重新產生、工具升級後對不上 |
| **每一章結尾一句「這一章的結論在哪裡停」** | 一篇 writeup 誤導讀者最常見的方式，就是不講它沒看哪裡 |

## W09 修稿時要做的三件事

1. **十分鐘測試**：假裝是陌生人，從第 1 章讀到第 14 章，計時。
   讀不完就是太長，砍掉的第一順位是第 7 章的表格細節與第 9 章的機制說明。
2. **每一條主張追一次產物**：隨機抽十句，每一句都要在 `reports/` 或 `notes/`
   或 `BENCH-LOG.md` 找得到出處。**找不到的那一句是這一輪最重要的產出。**
3. **第 12 章和第 14 章各讀一次，讀到不舒服為止。** 不舒服代表寫對了；
   如果讀起來很得意，那是這兩章被寫壞了。
